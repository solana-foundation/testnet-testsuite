# Review: Manifest client and orchestrators, mtm-chain, mtm-dex-harness, Manifest SDK

Scope: `crates/manifest-dex-client`, `crates/manifest-dex-orchestrator`,
`services/manifest-dex-orchestrator`, `crates/mtm-chain`,
`crates/mtm-dex-harness`, `crates/sdks/manifest` (generated; reviewed for how
it is produced and wrapped).

Reviewed 2026-10-14 at `bc96670`, read-only. Severity is
Critical/High/Medium/Low. Priority runs from P0 (now), P1 (next) and P2
(later) to P3 (nice to have). Two findings were re-verified while compiling
this report: the exact-in quote check in Manifest client #1, and the stale
codegen target in SDK #1. The dust scenario itself was traced by hand, not run.

## mtm-chain

**Purpose and boundary.** The shared transaction layer. `ChainClient` wraps one
`Arc<RpcClient>`, and `submit` builds, signs once, simulates, sends and
confirms. It is meant to be the only place transactions get submitted, but it
only builds legacy `Transaction`s (`lib.rs:137`), so the v1 users (arb, flow,
the router) bypass it. It has no tests.

| #   | Severity | Category         | Finding                                                                                                                                                                                                                                                                         | Recommendation                                                                                                                                                    | Priority | Impact                                                                                                       |
| --- | -------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| 1   | High     | perf             | **Each transaction confirms on its own:** one `get_signature_statuses(&[sig])` plus one `get_block_height()` every 500 ms (`lib.rs:193-237`). N in-flight transactions make about 4N RPC/s, each holding an HTTP/1.1 socket. This is where the ~24k sockets at x2000 came from. | One shared confirmer: a channel of pending signatures, batched `getSignatureStatuses` (256 per call), one block-height ticker, and a semaphore on in-flight RPCs. | P0       | Rate limits and port or file-descriptor exhaustion at scale.                                                 |
| 2   | High     | perf/correctness | **The CU limit is always the configured 1.4M default** (`lib.rs:37,112-117`). The transaction is signed before it is simulated (`137-148`), so the simulated CU count can never set the limit.                                                                                  | Simulate unsigned at the max, then rebuild with simulated × 1.1-1.2 and sign.                                                                                     | P1       | Priority fees 5-50× too high; the scheduler books 1.4M per transaction against block and per-account limits. |
| 3   | Medium   | correctness      | **No rebroadcast.** The transaction is sent once (`skip_preflight`, `max_retries: Some(0)`, `163-165`) and re-sent only after transport errors. The 45 s timeout is shorter than a blockhash's life.                                                                            | Re-send the same signed bytes every ~2 s until `last_valid_block_height`; tie the timeout to expiry.                                                              | P1       | Dropped packets on testnet become ambiguous outcomes.                                                        |
| 4   | Medium   | correctness      | **One transient poll error is final.** A single 429 while polling returns `AmbiguousConfirmation` (`196-224`).                                                                                                                                                                  | Back off and keep polling until the deadline.                                                                                                                     | P1       | False ambiguity for transactions that landed.                                                                |
| 5   | Medium   | correctness      | **Classification after a transport retry is too definite.** If attempt 1 may have been delivered and attempt 2 returns a non-transport error, the result is a definite failure (`188`).                                                                                         | Once any attempt may have reached a validator, classify later failures as ambiguous.                                                                              | P2       | Caller resubmits; duplicate risk.                                                                            |
| 6   | Medium   | correctness      | **`tx.rs` `send_instructions` re-signs with a fresh blockhash after any error,** confirmation timeouts included (`tx.rs:61-75`). That contradicts `lib.rs`'s policy, and nothing calls it.                                                                                      | Delete `tx.rs`.                                                                                                                                                   | P1       | A latent double-execution trap.                                                                              |
| 7   | Medium   | boundary         | **No v1 or ALT path** (`137`).                                                                                                                                                                                                                                                  | `submit_v1` with the same signing, confirmation and classification.                                                                                               | P2       | Forces v1 users around the layer.                                                                            |
| 8   | Low      | standards        | **`&dyn Signer` isn't `Sync`** (`105-111`), so submission futures aren't `Send`.                                                                                                                                                                                                | `&(dyn Signer + Sync)`; the knock-on change is limited to the harness parameter types (`cli.rs:311-317,343-349,404-411`).                                         | P2       | Futures can't be `tokio::spawn`ed.                                                                           |
| 9   | Low      | correctness      | **Simulation and block height use the default commitment,** not `config.commitment` (`145,219`).                                                                                                                                                                                | Pass it explicitly.                                                                                                                                               | P3       | Skewed expiry check.                                                                                         |
| 10  | Low      | perf/ops         | **The HTTP client can't be tuned** (`85-90`): no timeout, pool or HTTP/2 setting.                                                                                                                                                                                               | A builder.                                                                                                                                                        | P2       |                                                                                                              |
| 11  | Low      | testing          | **The retry and classification state machine is untested.**                                                                                                                                                                                                                     | A mock `RpcSender` covering transport retry, ambiguous outcomes, expiry and execution errors.                                                                     | P2       | The riskiest code in the workspace is untested.                                                              |
| 12  | Low      | standards        | **Commitment parsing is duplicated** (`lib.rs:254` vs harness `cli.rs:26-49`).                                                                                                                                                                                                  | Take a `CommitmentConfig`.                                                                                                                                        | P3       |                                                                                                              |

**Design recommendations**

- **A confirmer actor (L).** It owns batched statuses, shared block-height and
  blockhash caches, and rebroadcast; `submit` awaits a oneshot. Fixes #1, #3
  and #4 and the socket blow-up.
- **Simulate, then size (S)**; the configured limit becomes only a ceiling.
- **A typed `Pending { signature, last_valid_block_height }` outcome (M),** so
  callers reconcile instead of guessing.
- **Delete `tx.rs`; add a v1 path (S/M).**

## mtm-dex-harness

**Purpose and boundary.** Three things in one crate:

- `spl`: pure SPL, ATA and System builders and decoders;
- `funding`: test-token minting in a single transaction;
- `cli` (a feature): env keypairs, shared clap groups, and the ephemeral-user
  lifecycle.

"Harness" is the wrong home for `spl`, because `manifest-dex-client` and
`orca-whirlpool-client` depend on a harness crate to get core SPL helpers.

| 2   | Medium   | perf            | **Funding and flows are fully sequential** (`221,256`).                                                                                                                                                                              | Fund lazily; bounded concurrency.                                             | P2       | Unusable for load.                   |
| 3   | Medium   | correctness     | **Reclaim never unwinds venue state** (seats, orders) (`311-341`).                                                                                                                                                                   | A per-venue cleanup hook before reclaim.                                      | P2       | Funds locked in markets.             |
| 4   | Low      | ops             | **Recovery noise.** Reclaim errors are swallowed during funding failure (`240`), and recovery files are left behind for users that were fully reclaimed.                                                                             | Log; remove those files.                                                      | P3       |                                      |
| 5   | Low      | correctness     | **A possibly stale balance read before the final transfer** (`326-330`).                                                                                                                                                             | `min_context_slot`.                                                           | P3       | Dust or a failed transfer.           |

| 9   | Medium   | boundary        | **`spl` is depended on by client crates,** while the Raydium CLI re-implements all of `cli` (`raydium main.rs:399-725`).                                                                                                             | Move `spl` to `mtm-chain` or `mtm-spl`; migrate Raydium.                      | P2       | The same logic copied in two places. |

**Design recommendations:**

- An `EphemeralUser` guard plus a `Venue::cleanup` trait, so reclaim always
  runs and concurrency becomes safe (M).
- Split `spl` out, and keep the harness CLI/test-only (S).

## manifest-dex-client

**Purpose and boundary.** High-level Manifest actions (market, seat, deposit,
withdraw, batch orders, SwapV2) plus a pure book decoder and quoter
(`book.rs`). No GPL dependencies are linked. Everything goes through
`mtm-chain::submit`.

**Verified correct:**

- the 256-byte `MarketFixed` and its mint offsets;
- the 80-byte red-black-tree blocks, walk and guards;
- `price_raw × base / 1e18` with the program's rounding law;
- expiry handling;
- slippage rounding against the trader.

| #   | Severity | Category    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Recommendation                                                                                                                 | Priority | Impact                                                                                         |
| --- | -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | -------- | ---------------------------------------------------------------------------------------------- |
| 1   | High     | correctness | **Quote-to-base exact-in swaps are rejected whenever rounding leaves dust.** `impact_base_atoms` floors the base, so the matched quote is usually less than `amount_in`, and `quote()` rejects `input != amount_raw` (`lib.rs:204-208`). Traced: asks 100@1.5 and 100@2.0 with 251 quote in gives "absorbs only 250 of 251". Only the evenly divisible case is tested (`book.rs:428`). Every Manifest route goes through this (`mtm-venues lib.rs:281-309`). | Fail only when the unspent input is at least one tick (or above a dust threshold); send `in_atoms = amount_raw`; add the test. | P1       | Most quote-in Manifest swaps fail client-side, and routing silently shifts away from Manifest. |
| 2   | Medium   | correctness | **Post-action reads aren't pinned to the confirmation slot** (`766-777,516,571,647,683`).                                                                                                                                                                                                                                                                                                                                                                    | `min_context_slot`, or transaction-meta deltas; batch the four balance reads.                                                  | P1       | False "delivered X of Y" after confirmation, so a caller retry duplicates the trade.           |
| 3   | Medium   | perf        | **Heavy reloads.** Every action reloads market and mints (3 RPCs) 2-3 times. Seats are never released, so the market account and its parse cost grow with every ephemeral user, and `seat()` is a linear scan.                                                                                                                                                                                                                                               | Cache mints and programs; return the snapshot from actions; look up seats lazily; reuse a fixed set of seats.                  | P2       | Makers and flows slow down as the market grows.                                                |
| 4   | Medium   | correctness | **Errors lose information.** A transport `SimulationRpc` becomes `SimulationFailure` (`941-944`), and `Execution { signature, slot }` is flattened to a string (`948`).                                                                                                                                                                                                                                                                                      | Keep distinct variants and the signature.                                                                                      | P2       | Callers can't tell "landed, failed, paid a fee" from "never sent".                             |
| 5   | Medium   | correctness | **Cancels pass stale index hints, and batches aren't sized.** The `order_index_hint` comes from a pre-submit snapshot (`637-640,670-673`); the program's behaviour on a stale hint is unverified. Batch size isn't chunked (`619-645`).                                                                                                                                                                                                                      | Verify; drop hints if a stale one fails the batch; chunk.                                                                      | P2       | `replace_orders` failures under concurrent takers.                                             |
| 6   | Low      | correctness | **The snapshot slot comes from a separate `get_slot`** (`108-117`), contrary to the doc comment.                                                                                                                                                                                                                                                                                                                                                             | Use the context slot.                                                                                                          | P3       |                                                                                                |
| 7   | Low      | correctness | **Unchecked `10_u128.pow(decimals)`** (`1190`).                                                                                                                                                                                                                                                                                                                                                                                                              | `checked_pow`.                                                                                                                 | P3       |                                                                                                |
| 8   | Low      | correctness | **Price conversion always rounds down** (`lib.rs:1186-1197`).                                                                                                                                                                                                                                                                                                                                                                                                | Round bids down and asks up.                                                                                                   | P3       | Asks posted about one ULP inside the spread.                                                   |
| 9   | Low      | correctness | **A strict borsh `OrderType`** (`book.rs:262`): one unknown variant fails the whole book parse.                                                                                                                                                                                                                                                                                                                                                              | Decode as a raw `u8`.                                                                                                          | P3       | Fragile if the fork adds a variant.                                                            |
| 10  | Low      | standards   | **Hygiene.** A 7-argument `new`; a stray block in `batch`; an `async fn` that never awaits; "confirmed" recorded for no-op paths.                                                                                                                                                                                                                                                                                                                            | Tidy; take a `SubmissionConfig`.                                                                                               | P3       |                                                                                                |
| 11  | Medium   | testing     | **The decoder tests are circular:** they serialize with the same SDK they decode with (`book.rs:497-565`).                                                                                                                                                                                                                                                                                                                                                   | Golden base64 dumps of real accounts plus recorded swap results.                                                               | P2       | Layout drift goes unnoticed.                                                                   |
| 12  | Low      | licensing   | **The doc comment says the code "mirrors the program's `place_order` loop"** (`book.rs:10-17`). The code itself is clean.                                                                                                                                                                                                                                                                                                                                    | State that the logic derives from the IDL and observed behaviour, to keep the clean-room claim defensible.                     | P3       | Audit trail.                                                                                   |

**Design recommendations:**

- Fix the dust rule now (S).
- Actions return post-state at `min_context_slot` (S/M).
- A `MarketCache` and lazy seat lookup (M).
- Golden fixtures from the deployed fork (M).

## Cross-cutting notes

- **`mtm-chain` is not the single submission layer.** Arb builds v1
  transactions and simulates and sends directly (`arb/search.rs:293-307`). The
  router fetches its own blockhash (`assemble.rs:310-320`). The Raydium CLI
  duplicates the reclaim and transfer helpers. The root cause is that `submit`
  is legacy-only; a v1 path fixes it.
- **Ambiguous outcomes are never reconciled.** Every client turns
  `AmbiguousConfirmation` into an error, and any higher-level retry is a
  duplicate-execution risk. Combined with stale post-confirmation reads, this
  is the main double-trade path.
- **Order of scale fixes:** per-transaction polling (chain #1), then the 1.4M CU
  limit (chain #2), then sequential ephemeral users (harness #2), then seat
  growth (client #3).
- **Rules check.** Fixed-point compliant (Decimal and checked u128; f64 only in
  metrics). Granular Solana crates with the 4.2.1 floor. No GPL code linked.
