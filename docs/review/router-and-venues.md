# Review: router service, mtm-venues, router-client

Scope: `services/router`, `crates/mtm-venues`, `crates/router-client`.

Reviewed 2026-10-14 at `bc96670`, read-only. Severity is
Critical/High/Medium/Low. Priority runs from P0 (now), P1 (next) and P2
(later) to P3 (nice to have). The CPU and RSS root causes below are inferred
from the code paths, not profiled.

## services/router

**Purpose and boundary.** An axum HTTP service with four parts:

- a pool registry: curated pools plus discovered and vetted ones;
- a per-quote snapshot loader with a TTL cache;
- a pure planning engine: exact-in splits, 2-hop bridges, single-hop exact-out;
- v1 transaction assembly: direct venue instructions, or Jupiter `route_v2`.

The service-dependency rule holds. Inside the crate the layers are mixed:
`lib.rs` holds the cache and the loader, and the engine builds the wire
response.

**Design recommendations**

- **Arc snapshot store with background refresh (M).** An `ArcSwap` of
  `Arc<PoolSnapshot>` refreshed per pool (batched across pools via
  `getMultipleAccounts`). Quotes never wait on RPC, and each snapshot carries
  its slot. This addresses R1, R3, R4, R6 and R10, and is a step toward the
  ws/Geyser cache in the design doc.
- **Pair-indexed registry with structural tiers (S).** Re-validate and evict
  periodically; optionally persist for fast restarts (R7, R8, R10).
- **Footprint-aware planning (M).** `LegQuote` returns accounts, bytes and CU,
  so the engine plans within v1 budgets and the fit-retry loop goes away (R17,
  R18).
- **Typed errors end to end (S)** (R5, R6, V3).
- **CU model (S):** swap and ATA constants calibrated from `venue_*_cu` p99,
  with a percentage margin (R11).

## crates/mtm-venues

**Purpose and boundary.** A venue-agnostic `PoolSnapshot` over the three
clients (load, quote, instructions), plus discovery and a Jupiter `route_v2`
encoder. Used by the router, arb, mm and mtm-scenario. It mixes RPC I/O with
pure quoting, and holds an aggregator encoder that only the router needs.

**Design recommendations**

- **Pure layer and I/O layer (M):** pure snapshot, quote, footprint and CU
  helpers, plus a loader that batches across pools with slot-tagged results.
  A push cache can later replace the loader.
- **`Arc`-backed snapshots and non-mutating quote math (M).** This is where
  the router, arb and mm CPU actually goes.
- **Move the Jupiter encoder to its own client crate (S).**

## crates/router-client

**Purpose and boundary.** The router's HTTP wire types plus a thin reqwest
client. It is used only by flow and the router examples. Structurally clean;
semantically it has gaps.

| #   | Severity | Category        | Finding                                                                                                                                                              | Recommendation                                                | Priority | Impact                               |
| --- | -------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | -------- | ------------------------------------ |
| C1  | Medium   | correctness/ops | **`error_for_status()?` throws away the body** (`lib.rs:144,160`), so the router's 404/422/502 messages never reach flow.                                            | An `Api { status, message }` error variant.                   | P1       | Flow failures can't be diagnosed.    |
| C2  | Medium   | ops             | **No timeout** (`lib.rs:132`).                                                                                                                                       | A builder that defaults to a few seconds.                     | P1       | Flow stalls on an overloaded router. |
| C3  | Medium   | correctness     | **Contract gaps.** No `max_in_amount`; `price_impact_bps` is always 0; `state_slot` doesn't match its documentation; `venue` is a free-form string (`lib.rs:53-76`). | Fix the fields; make `venue` an enum shared with `VenueKind`. | P1       | Exact-out risk can't be bounded.     |
| C4  | Low      | standards       | **Ergonomics.** Free default functions instead of `#[derive(Default)]`; no typed `/v1/pools`; no serde round-trip tests.                                             | Fix all three.                                                | P3       |                                      |

**Design recommendations:**

- Golden JSON fixtures shared with the router tests, so the server and client
  can't drift (S).
- Retry 502/503 with jitter, never 4xx (S).

## Cross-cutting notes

- **Root causes of the load-run numbers:**
  - copies per quote (R1, V1, R2);
  - RPC per quote: the cache is off by default (R3) and loads waste RPCs
    internally (V2);
  - the cache map is bounded by pool count, so it is not a leak, but it keeps a
    full snapshot per pool alive. Profile with a heap profiler once `Arc` is in
    place.
- **Snapshot consistency.** Raydium reads the pool and its tick arrays in
  separate calls (raydium `lib.rs:921` vs `1482-1510`), the race the Orca
  client explicitly re-reads to avoid (orca `lib.rs:1241-1245`).
- **The 50k CU margin is hard-coded in three places.** Centralize it with
  calibrated constants in `mtm-venues`.
- **A shared mock loader trait** would let the router, arb and mm test their
  I/O edges without a validator.
