# Review: scenario service, bootstrap tooling, token bootstrap, ops config

Scope: `services/scenario`, `bootstrap/scenario` (scripts), `bootstrap/tokens`,
the justfile scenario recipes, and `ops/`.

Reviewed 2026-10-14 at `bc96670`, read-only. Severity is
Critical/High/Medium/Low. Priority runs from P0 (now), P1 (next) and P2
(later) to P3 (nice to have). Service #1 and #2 were re-verified while
compiling this report.

## scenario (service)

**Purpose and boundary.** The operator CLI: bootstrap, status, token-count,
snapshot, report, teardown and leftovers. It runs over `mtm-scenario`, the
venue clients and the `*-orchestrator` libraries. No service-crate
dependencies, though depending on the orchestrator libraries goes against the
literal "only `*-client` crates" rule (see `README.md` in this folder).
`pnl.rs` handles chain reads, venue valuation, block scanning, Prometheus
queries and report math in one file, with no tests.

**Design recommendations**

- **Split `pnl.rs` (M)** into `snapshot` (reads), `valuation` (pure),
  `blocks` (scanner), `metrics` (Prometheus) and `report` (pure math over two
  snapshots plus a transaction index).
- **Move raw JSON-RPC into `mtm-chain` (S-M):** typed `token_accounts_by_owner`,
  `get_block_accounts` and `program_accounts_slice` helpers with error checks,
  retries, the client's commitment and one HTTP client. This fixes #1, #2, #5
  and #11 at once and removes three hand-rolled copies.
- **Slot-anchored snapshots (M):** context slots or `minContextSlot`, with the
  spread recorded.
- **Per-participant transaction counts on testnet (S):** `network.*` counts
  everyone's traffic on a shared cluster.

## bootstrap/scenario tooling (scripts)

**Purpose and boundary.**

- `scenario.sh` orchestrates processes: build, tokens, pid-file supervision,
  freeze/measure, teardown, observe.
- The Python scripts generate configs (`scale.py`, `dashboard.py`), sample load
  (`sample.py`), summarize runs (`summarize.py`), and build the Metaplex
  snapshot.

Process supervision and the measure protocol are drifting into bash, where
they would be safer in Rust or under a real supervisor.

**Design recommendations**

- **Move `measure` into Rust (M):** freeze and thaw with guaranteed CONT on
  drop or signal, then snapshot, sample, snapshot, and report while frozen,
  with retries. Bash only launches it.
- **One process supervisor (S-M):** a `stop` with escalation and liveness
  checks, or `systemd-run --user` / process-compose (#4, #8, #11).
- **One secret-file helper (S):** process substitution only.

## Cross-cutting notes

- **Silent fallbacks are the main correctness theme.** RPC and Prometheus
  errors become zero or empty values (`pnl.rs:392,340,297,356,464`,
  `teardown.rs:596,616,653`). In a measurement tool, every fallback should be
  either fatal or listed in `warnings`.
- **One RPC layer.** Hand-rolled JSON-RPC exists in three places with different
  error handling and commitments.
- **Testnet readiness.** Network-wide counters and gPA scans assume a private
  chain. On testnet, filter to participant signers, cache market addresses, and
  expect public-RPC limits on `getBlock`.
- **The freeze isn't enough on testnet.** Pair SIGSTOP with slot checks and an
  expiry-based settle, and keep flow stopped through the report.
- **CI gaps:** no shell, Python or TypeScript checks.
